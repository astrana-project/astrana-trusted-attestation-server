# 11. Support PostgreSQL, MySQL and SQL Server, one schema each

Accepted on 2026-10-05.

## Context

Organisations pick the database they already run ([record 9](0009-use-a-relational-database.md)), and each supported
database adds its own version of every procedure and role grant to write, maintain and test, so the set has to stay
small.

## Decision

Support PostgreSQL, MySQL and SQL Server. Each has its own hand-written schema file in `shared/schema`, behaviourally
equivalent, with the procedures named identically, and each implementation supports all three and resolves the driver
differences at runtime. The schema files are the source of truth, not any framework's model.

## Consequences

- SQL Server and PostgreSQL are the enterprise-grade choices in the environments the implementations serve, and MySQL is
  everywhere. Two of the three are open source, which this project prefers where the choice is free, and SQL Server is
  the exception because the Microsoft ecosystem is one of the three environments the project exists for.
- The files are hand-written per dialect because the procedures and roles must be explicit and auditable. Each engine
  also needs its own privilege and transaction handling to make the boundary hold. On PostgreSQL the procedures run with
  their definer's privileges. On MySQL each procedure is wrapped in an explicit transaction, because its statements
  otherwise commit one by one. On SQL Server a setting rolls a procedure back entirely on any error, and a unique index
  ignores rows that have no key yet. PostgreSQL needs no explicit transaction, because a procedure call there is atomic,
  and no filtered index, because its unique constraint already admits any number of rows without a key.
- The database checks, which run against any of the three engines, confirm that the dialects behave the same.
- MySQL support brings in Oracle's driver for .NET and Java, accepted under the dependency rule
  ([record 6](0006-keep-third-party-dependencies-to-a-minimum.md)), and PHP uses its own `pdo_mysql` extension. MariaDB
  is not tested and not supported, though the MySQL schema file and PHP's driver seam accept it.
- Oracle Database is not supported. It is concentrated in large banks and government agencies rather than widespread, it
  is not open source and nor are its drivers, and PHP would need Oracle Instant Client in its image, a second
  closed-source client beside the Microsoft Open Database Connectivity (ODBC) driver that SQL Server already requires
  there. The per-dialect schema files and the per-driver seams in each implementation leave room for a fourth engine.
- A schema generated by the framework was rejected because the procedures and roles must be read as written.
